No Bedrock access?

Use the Groq editions

New AWS accounts often can’t call Bedrock models: Free-plan accounts commonly report zero Bedrock quotas, and Anthropic models need an AWS Marketplace subscription, which the Free plan restricts. So every notebook and script that uses a Bedrock model has a _groq twin next to it — the same agent code, with the model running on Groq instead. Groq has an OpenAI-compatible API, so Strands’ OpenAIModel talks to it; nothing else in the lesson changes.

Switch a section to Groq
# in each section, instead of requirements.txt
pip install -r requirements-groq.txt

# repo root; free key at https://console.groq.com/keys
echo "GROQ_API_KEY=gsk_..." > .env

# checks the key, the models, and (optionally) AWS/AgentCore
python setup/check_setup_groq.py

No Bedrock anywhere

The guardrails notebook replaces Bedrock Guardrails with a Groq safety model (openai/gpt-oss-safeguard-20b) plus PII rules in code; the evaluation notebook judges with a Groq model through the open-source Strands Evals SDK instead of AgentCore Evaluations (whose judges are Bedrock models).

AgentCore needs a Paid-plan account

AWS lists Amazon Bedrock AgentCore as “Paid plan exclusive” on the Free Tier page. Upgrading keeps your Free Tier credits. The AgentCore labs use no Bedrock models.

Models

The default is openai/gpt-oss-120b; change it everywhere with export GROQ_MODEL_ID=openai/gpt-oss-20b (or qwen/qwen3.8-27b).

Free-tier limits

About 8,000 tokens per minute and 200,000 tokens per day per model. Short waits (rate limit) retry automatically. Request too large ... (TPM) means one request is bigger than 8,000 tokens — waiting won’t help; start a fresh conversation or shorten the input. If you hit the daily limit, switch GROQ_MODEL_ID to another model or upgrade to Groq’s Dev tier.

Run on a local model instead

Anything that runs on your machine can use a local OpenAI-compatible server such as Ollama: ollama pull llama3.1, then export GROQ_BASE_URL=http://localhost:11434/v1 GROQ_API_KEY=ollama GROQ_MODEL_ID=llama3.1. Small local models are slower and less reliable with tools; deployed labs (AgentCore, ECS, Lambda) can’t reach a model on your laptop; and the two LangChain/LangGraph files use Groq’s own client (langchain-groq), so they stay on Groq.

Permissions

Use a sandbox / learning account, not a production one. There, an administrator user is simplest. Otherwise attach setup/iam-policy-course.json to your user or role — it covers every lab in the course. It is deliberately broad (the labs create IAM roles, gateways, Lambda functions and more), so treat it as sandbox-only.

Model access

Amazon Bedrock serverless models are available by default — no request form. The labs use:

ModelID used in code
Claude Sonnet 4.6 (default)global.anthropic.claude-sonnet-4-6
Claude Haiku 4.5 (fast/cheap: memory, evaluation judge, Lambda)global.anthropic.claude-haiku-4-5-20251001-v1:0

The global. prefix is a cross-Region inference profile: Bedrock routes each request to the best Region automatically, and it works from any supported source Region (including India).

When things break

5Troubleshooting

AccessDeniedException calling Bedrock

Check IAM permissions and that AWS_REGION is set.

ValidationException ... model identifier is invalid / “on-demand throughput isn’t supported”

Use an inference-profile ID (with global. or us.), as in the model table above.

ResourceNotFoundException ... Legacy model / end-of-life

That model was retired — set BEDROCK_MODEL_ID to a current model.

ThrottlingException

Wait a minute and retry; use Haiku for bulk runs.

ModuleNotFoundError in a notebook

Run the %pip install -r requirements.txt cell, then restart the kernel.

Port already in use (Sections 5–7)

Stop the old process (lsof -i :9001) or docker rm -f <name>.
